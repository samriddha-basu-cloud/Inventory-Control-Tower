# Deployment

## Render

`render.yaml` defines:
- A `web` service running `gunicorn run:app` (2 workers, 4 threads, 120s
  timeout), buildable with `pip install -r requirements.txt`.
- A managed Postgres database (`ict-postgres`), wired to the web service via
  `DATABASE_URL` (Render's `fromDatabase` reference).
- `SECRET_KEY` auto-generated by Render; `ENVIRONMENT=production`.

`Procfile` mirrors the same `web` process for any Heroku-compatible
platform, plus a `release` phase that runs `db.create_all()` before the app
starts serving traffic (no Flask-Migrate/Alembic migrations are set up yet -
`db.create_all()` is idempotent and additive but does **not** alter existing
columns; see `known-limitations.md`).

Steps on Render:
1. Push this repository to GitHub.
2. New → Blueprint → point at the repo → Render reads `render.yaml`.
3. Deploy. The `release` command creates tables on the provisioned Postgres
   database.
4. Open the app and click **Launch Demo** to load the synthetic network
   (or call `POST /demo/launch`).

## Local development

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
python run.py
```

Defaults to SQLite at `instance/ict.db`. Set `DATABASE_URL` to point at
Postgres locally if you want parity with production.

## Environment variables

| Variable | Purpose | Default |
|---|---|---|
| `DATABASE_URL` | SQLAlchemy connection string | `sqlite:///instance/ict.db` |
| `SECRET_KEY` | Flask session signing | `dev-secret-key-change-me` (change in production) |
| `ENVIRONMENT` | `development` \| `production` \| `testing` | `development` |
| `UPLOAD_LIMIT_MB` | Max upload size | `25` |

No secrets are committed; `.gitignore` excludes `.env`, `instance/`, and any
`*.db`/`*.sqlite*` files.
