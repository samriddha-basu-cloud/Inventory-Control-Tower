# Industry Configuration Engine

One shared codebase, not a forked codebase per vertical (section 151).
`app/utils/industry_profiles.py` defines lightweight profiles:

| Profile | Allocation rule | Emphasis KPIs |
|---|---|---|
| `fmcg` (default, used by the demo) | FIFO | fill rate, DOS, excess value, turns |
| `pharma` | FEFO | expiry exposure, cycle service level, quarantine value, OTIF |
| `automotive` | priority customer | line risk, component shortage, OTIF, safety-stock coverage |
| `electronics` | margin | obsolescence exposure, excess value, last-time-buy risk |
| `spare_parts` | priority customer | fill rate, criticality coverage, intermittent-demand risk |

`Organization.industry_profile` selects the active profile. What actually
changes per profile in this build is the FEFO-vs-FIFO default and which KPIs
would be emphasized first on a profile-aware dashboard; the models, formulas
and workflow are shared.

## What's honest to say about this

The profile registry exists and is wired to `Organization`, but the current
dashboard does not yet branch its layout by profile (that's a small,
well-scoped next step - see the README's "recommended next phase"). Only one
sample dataset (FMCG) is generated by `demo_data_service.py`; pharma,
automotive, electronics and spare-parts sample datasets are declared in the
profile registry (`sample_dataset` key) but their generators are not yet
implemented. Do not claim a pharma/automotive/electronics demo exists until
those generators are written.
